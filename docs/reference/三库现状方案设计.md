## 二、service：当前架构

### 2.1 接口契约（不碰层）

- `POST /add`：`{request_id,user_id,session_id,messages[{role,content,timestamp?}]}` → Receipt 恰 4 字段 `{success,request_id,user_id,session_id}`。**timestamp 可选**（官方样本无逐消息时间戳，P0-A），缺失时走合成序 `time_basis:'ordering'` + `[Session time: …]` 会话锚。
- `POST /search`：`{query,user_id,top_k,options?}` → `{data:[{id,content,score,created_at}]}`，只返证据。
- `GET /health`：引擎就绪即 2xx；探测结果 `models:"ok"|"degraded"` 如实上报不阻断（部分网关无 /models）。
- 幂等：`requests` 表（request_id+payload hash），重复同载返回原 Receipt，异载 409；REVISION_CONFLICT 串行队列内重试。

### 2.2 写入管道（server → engine 串行队列 → 事务提交）

```
zod 校验 → PreparationLedger 幂等 → extraction（offline 确定性 | enhanced 模型）
  → binding（resolveOperationTargets：槽位+值摘要+短语绑定）
  → 擦除范围语义审查（erasurePlan：erase/retain+值见证）→ transitions（同槽状态转移）
  → source operations（v6+ 路由/分批）→ source erasure（v4+ 原文分级切除）
  → storage.commit：单事务写 facts/markers/messages/passages/events/operations/FTS/receipt
```

- **双模式提取**：offline=确定性规则（评测主形态）；enhanced=模型提取+分片（extraction-shards）+具名核验协议（verification* 家族，上游合并后含预算内一轮协议修复与坏 JSON 有界恢复）+write-continuation 续传（release 关闭，契约③严格）。
- **降档哲学（R15 固化，R18 双模式合成）**：语义/能力二分——`OPERATION_*`/`EVIDENCE_VALIDATION` 的语义面 fail-closed 503（原子拒绝，绝不假 200）；网络/超时/坏 JSON/核验不可达等能力故障降档为确定性方案 200+degraded 标记。这是基座两轮 0/100 死穴的关闭机制。
- **时间**：temporal.ts 双形时间（time_text 原样 + 锚），合成序哨兵不充当日期锚（R19 修复：哨兵不再穿透 messageAnchors 继承）。

### 2.3 遗忘/擦除体系（R19+R20+评审轮之后的完整形态）

擦除是三层联动（事实层 / 原文层 / 派生层）：

1. **绑定**：叙事措辞→操作对象。值摘要（valueDigest=规范化词序哈希）、槽位（subject+propertyFamily+scope）、短语绑定（narrative phrase→PhraseEchoIndex）。R20 后接住四类残留形态：同消息强调尾句（anaphoricMirror 镜像头操作）、无包装定指短语（theNounForget）、程序性祈使守卫（operation-intent 防菜谱误伤）、纯数字令牌退休句。
2. **边界持久化**：markers 表存 ErasureBoundary（subject/predicate/scope/boundary/valueHash/tokenCount/phraseEcho 哈希索引/allowedValueHashes），**无明文值**（F4：PhraseEchoIndex{t,p,titles,lengths} 全哈希）。
3. **回声抑制**（echoMentions，当前 main 形态=上游重构+补投）：
   ```
   精确序列命中 → 真
   领格锚定分支（≥3 token：开头领格 bigram+头名词，免回指措辞）→ 真   ← followup 补投
   PRIOR_REFERENCE 显式回指（"as I mentioned"/"clear out the … stuff"）
     且不指向不同实体（namesDifferentEntity）→ bigram 阶梯（2-token 单 bigram / ≥2 bigram / 头衔姓氏宽限）
   ```
   反例固化：数字子串不连坐（F1 整 token）、单 bigram 新记录存活（F2，Alice Van Jones）、trace 描述符无值（F3）、marker 无明文（F4）、同主语不同属性存活（signing bonus）。
4. **连坐收窄**（R19 三层入口统一）：同槽或共享源才连坐，跨槽独立记录留 retain 存活；擦除核验降级与 storage 泄漏传播同口径。
5. **聚合卡成员粒度擦除**（R17，契约④）：卡（kind:'reflection'）永不连坐兄弟成员消息；restore 成员后家族卡重建。
6. **源擦除**（v4+）：原文分级切除（maskSource）、混合引文净化、已擦见证推进断言（assertErasedWitnessProgress）、保留值上下文校验（validateRetainedValueContexts）。

### 2.4 检索管道

```
text.ts intent（CUR/HIST/TRAJ 三分 + 题面候选四级梯[精确→数字集→短串→长文本语义]）
  → storage.lexical：FTS5 porter unicode61 BM25（facts 表 + passage 表双通道）
  → retrieval.ts 仲裁：同槽冲突值相对分离、R3 多源佐证 ×1.5（独立 source_ids≥2，不翻转状态）、
     聚合卡压制散值、operation 事件视图加成（MEMORY_EVENT_VIEW）
  → packing：coveragePacking + MEMORY_TOKEN_BUDGET（6000）+ MEMORY_MAX_EVIDENCE（32）
```

### 2.5 固化契约（测试守卫，改动需用户决策）

① 退休指令不可绑定=原子拒绝（OPERATION_TARGET 503，绝不静默跳过）；② 语义拒绝不降级（坏 JSON≠语义拒绝）；③ writeContinuation 严格契约（release 关）；④ 聚合卡成员粒度擦除。

### 2.6 评测形态关键配置（release-offline.env，A/B 实测口径）

MEMORY_MODE=offline、MEMORY_RETRIEVAL=lexical、EVENT_VIEW/AGGREGATE/CORROBORATION/LIFECYCLE/TEMPORAL/COVERAGE_PACKING=true、MAX_EVIDENCE=32、TOKEN_BUDGET=6000、ADD_TIMEOUT=115s、SEARCH_TIMEOUT=55s、EXTRACTION_WORKERS=1。

### 2.7 模块地图（40 文件按职能）

- 契约/配置：types.ts（zod+slot/canonical/propertyFamily）、config.ts
- 提取：extraction.ts（含 R20 提取门：experience 事实放宽至三人称/大写人名对——A/B 净 +15 的来源）、extraction-groups/shards、prompts、proposal-input

- 操作/擦除：binding、operation-intent、erasure、source-erasure(-grouped/-execution)、source-operations(-routing/-batches)、source-coverage、source-references、transitions
- 存储/检索：storage（事务+FTS）、retrieval(-policy)、reranking、passages、text、temporal、events
- 服务：server、engine（串行队列）、db-worker、write-continuation、preparation-ledger
