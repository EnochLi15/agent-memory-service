 六、接口契约（红线约束）
 6.1 三个必实现接口
 ┌────────┬──────────────┬─────────────────────────────────────────────┬───────────────────────────────────────────────┬────────────────────────────────────────────────┐
 │  接口  │     方法     │                    入参                     │                     出参                      │                     硬约束                     │
 ├────────┼──────────────┼─────────────────────────────────────────────┼───────────────────────────────────────────────┼────────────────────────────────────────────────┤
 │ Add    │ POST /add    │ request\_id, user\_id, session\_id, messages[] │ {"success": true, 三ID回显}                   │ 同步写入，返回 200 后立即可检索；禁止 202/异步 │
 ├────────┼──────────────┼─────────────────────────────────────────────┼───────────────────────────────────────────────┼────────────────────────────────────────────────┤
 │ Search │ POST /search │ query, user\_id, top\_k=100, options?         │ {"data":[{id, content, score?, created\_at?}]} │ 只返回证据，不生成答案；≤top\_k 条              │
 ├────────┼──────────────┼─────────────────────────────────────────────┼───────────────────────────────────────────────┼────────────────────────────────────────────────┤
 │ Health │ GET /health  │ 无                                          │ 任意 2xx                                      │ 无鉴权                                         │
 └────────┴──────────────┴─────────────────────────────────────────────┴───────────────────────────────────────────────┴────────────────────────────────────────────────┘
 6.2 契约硬约束
 \- 接口字段、成功/失败约定与 AML Textual 轨 Add/Search 契约对齐（详见 api\_contract.md）
 \- 契约校验失败 = 该次评测失败（整次客观评测无效）
 \- top\_k 正式评测固定为 100，返回条数不得超过此值
 \- user\_id 为检索隔离键，禁止跨样本串记忆
 6.3 超时约束（含下限）
 ┌──────────────────────┬─────────────────────────────────────┐
 │         调用         │              超时范围               │
 ├──────────────────────┼─────────────────────────────────────┤
 │ GET /health          │ 评测机设独立就绪检查超时            │
 ├──────────────────────┼─────────────────────────────────────┤
 │ POST /add（单次）    │ 1–120s（响应 <1s 且不合规也判失败） │
 ├──────────────────────┼─────────────────────────────────────┤
 │ POST /search（单次） │ 1–60s                               │
 └──────────────────────┴─────────────────────────────────────┘
 \- 超时、连接失败或连续 5xx：该次请求按评测机规则记失败
 \- 评测机对瞬态错误可有限重试（次数以赛题组配置为准）
 \- 同分时参考可用性、超时率等稳定性指标
 6.4 评测流程
 对每个样本（110 个）：
 1\. 按 session 逐个 Add（超 20 条消息/2000 词时评测机自动分 chunk）
 2\. 全部 Add 成功后，对该样本每道题调一次 Search(query, user\_id, top\_k=100)
 3\. 平台将 Search 返回的 content 填入固定 Answer 模板 → 生成答案
 4\. 固定 Judge / 规则对照 gold 计分（0/1，无部分分）

 七、评分规则
 7.1 总分公式
 最终得分 = 70% × 客观分 + 30% × 主观分
 7.2 客观分（70%）
 ┌─────────────┬─────────────────────────────────────────────────────────┐
 │     项      │                          规则                           │
 ├─────────────┼─────────────────────────────────────────────────────────┤
 │ 题量        │ 1000 题（LoCoMo 500 + MemOps 500）                      │
 ├─────────────┼─────────────────────────────────────────────────────────┤
 │ 每题分值    │ 0 或 1，无部分分                                        │
 ├─────────────┼─────────────────────────────────────────────────────────┤
 │ 子集权重    │ LoCoMo 50% + MemOps 50%（等权）                         │
 ├─────────────┼─────────────────────────────────────────────────────────┤
 │ 公式        │ S\_obj = 100 × (答对题数 / 1000)                         │
 ├─────────────┼─────────────────────────────────────────────────────────┤
 │ LoCoMo 判分 │ 主办方 LLM Judge → CORRECT=1 / WRONG=0                  │
 ├─────────────┼─────────────────────────────────────────────────────────┤
 │ MemOps 判分 │ gold\_rubric 规则为主，Judge 兜底                        │
 ├─────────────┼─────────────────────────────────────────────────────────┤
 │ 选手职责    │ 只负责记忆写入与检索；Answer/Judge/汇总由主办方统一完成 │
 └─────────────┴─────────────────────────────────────────────────────────┘
 附加记录（不进 S\_obj 公式）：
 \- 接口契约合规（校验失败则该次评测失败）
 \- 超时与可用性（并列时稳定性参考）
 \- MemOps 子维度（旧值率、泄漏、过遗忘）仅诊断报告
 \- 无记忆基线由主办方跑一次，用于报告相对提升
 7.3 主观分（30%）
 ┌────────────────────┬──────┬────────────────────────────────────────┐
 │        维度        │ 占比 │                评审内容                │
 ├────────────────────┼──────┼────────────────────────────────────────┤
 │ 方案与架构合理性   │ \~15% │ 记什么、怎么存、怎么召回、与短记忆边界 │
 ├────────────────────┼──────┼────────────────────────────────────────┤
 │ 工程质量与可部署性 │ \~8%  │ Docker/启动说明完整性、接口稳定性      │
 ├────────────────────┼──────┼────────────────────────────────────────┤
 │ 创新性与可扩展性   │ \~7%  │ —                                      │
 └────────────────────┴──────┴────────────────────────────────────────┘
 ▎ 具体细则以赛题组评审表为准
 7.4 评测时序
 \- 初赛客观分决定晋级
 \- 主观分在决赛综合
 \- 初赛阶段提交截止后统一评测（次数与窗口以赛题组通知为准）
 \- 非实时交互，批量离线跑分
