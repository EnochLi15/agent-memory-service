## 一、方案与架构合理性

### 1.1 总体架构

一套以「**状态机 + 事件锚 + 令牌化擦除边界**」为核心的同步记忆服务，单租户单 SQLite 事务、双源表示、两条管线：

```
                    ┌───────────────────────────────────────────────────┐
 POST /add ───────► │ 写入管线（全同步，单事务提交，返回即可检）              │
 (request_id,       │  zod 契约校验 → 幂等账本（request_id+载荷哈希）       │
  user_id,          │  提取：offline 确定性规则 ｜ enhanced 模型+分片+核验   │
  session_id,       │  操作绑定（槽位+值摘要+短语）→ 擦除范围语义审查         │
  messages[])       │  → 同槽状态转移核验 → 原文操作路由 → 原文分级切除      │
                    │  → 事务：facts/markers/messages/passages/events/FTS │
                    └───────────────────────────────────────────────────┘
                    ┌───────────────────────────────────────────────────┐
 POST /search ────► │ 检索管线：意图三分 → FTS5 porter BM25 双通道（事实+   │
 (query, user_id,   │ 原文段）→ 仲裁（冲突分离/多源佐证/聚合卡/操作事件）    │
  top_k, options?)  │ → 覆盖打包（token 预算+证据上限）→ 仅返证据           │
                    └───────────────────────────────────────────────────┘
 GET /health ─────► 引擎就绪 2xx；模型探测结果 models:"ok"|"degraded" 如实上报不阻断
```

三条设计定律（R1-R4 从评测结构归纳，实现全程受其约束，均已在实现中兑现）：

1. **粒度定律**——事实层（headline 式 content）之外保留**原文段层**（passages，贴原文分段、按来源关联事实），跨会话列表/多跳题由原文段兜底。
2. **链条定律**——同槽状态机（active/conflicted/superseded/retracted/erased）+ memory_events 全操作日志（含 forget，值不入日志只入状态 ID 引用），轨迹题与操作回溯直接可答。
3. **呈现定律**——检索侧仲裁保证当前值置顶、旧值降位标注；遗忘走擦除边界+回声抑制而非物理删除，leakage 与 over-forget 双指标同时成立。

### 1.2 记什么（提取）

- **双形态产出**：每条消息同时产出**结构化事实**（subject/predicate/value/scope/kind/modality/cardinality + 双形时间 + 逐字 source_quotes 佐证）与**原文段**（passage 分段、说话人、事实关联）——事实供状态与仲裁，原文段供兜底召回与擦除后可审计性。
- **modality 五态**：confirmed / tentative / hypothetical / quoted / inferred——假设值与引述值在检索侧直接被 `allowed()` 门挡（不入当前答案面），tentative 永不覆盖 confirmed（recency_trap 防御）。
- **确定性提取门（offline 形态）**：经验事实要求第一/三人称指称或大写人名对锚定（A/B 实证：此门放宽净 +14 配对分，A02 类"移除他"场景的保留语义靠它成立）。
- **防污染防回声**：assistant 回声只保留用户版本；对抗性祈使（菜谱"Remove from heat"）由程序性祈使守卫挡在遗忘之外。

### 1.3 怎么存（存储）

user_id 隔离域（目录哈希分租户），单 SQLite 连接全事务：

| 表 | 内容 |
|---|---|
| facts | 事实层：槽位（subject+属性族+scope）状态机；擦除后**值与内容抹除**仅留槽位与哈希 |
| passages / messages | 原文段层与消息层：searchable/redacted 标记，混合消息分级切除（partial） |
| markers | **擦除边界**：值哈希+词数+短语回声索引（全哈希，**无明文**）+ 允许回库值哈希 |
| memory_events / operations | 操作日志：类型/槽位哈希/前后状态 ID 引用/无值描述符 |
| evidence_fts / passage_fts | FTS5 porter unicode61 双通道（词干双侧归一） |
| requests | 幂等账本（request_id + 载荷哈希 → Receipt） |

**三类派生物写入期物化、带完整 provenance**：同槽多值聚合卡（kind:reflection，跨会话列表单卡全值，值串排序后原样嵌入）；多源佐证标记（独立来源数≥2 的 conflicted 值，检索侧 ×1.5 加成不翻转状态）；操作事件视图。派生物擦除按**成员粒度**（卡永不连坐兄弟成员、restore 成员后家族卡重建）——这是聚合视图与遗忘共存的关键结构。

### 1.4 怎么召回（检索）

```
search(query, user_k)
 1  意图三分（正则 v2，1,544 题全量验证零假阳性）：CURRENT / HISTORY(as-of) /
    TRAJECTORY（链存在才激活）+ 题面候选四级梯（精确→数字集守卫→短串→长文本语义）
 2  双通道召回：evidence_fts（事实）+ passage_fts（原文段）BM25 超采
 3  仲裁：同槽冲突值相对分离｜多源佐证 ×1.5｜聚合卡压制散值｜操作查询事件加成
 4  覆盖打包：token 预算（6000）内最大化来源覆盖，证据上限 32
 5  返回 {id, content, score, created_at}[] —— 绝不生成答案
```

### 1.5 遗忘与擦除（本方案最深的一层）

叙事措辞的遗忘指令（"please forget the Tucson detail"、"you can go ahead and remove him"）经**短语绑定**落到操作对象；执行时三层联动：事实层抹值、原文层分级切除（只删授权跨度、保留无关邻句）、派生层依赖传播。防泄漏三道锁：**值摘要匹配**（规范化词序哈希，整 token 无子串连坐）、**哈希短语回声索引**（换词复述 ≥2 共享 bigram 抑制；领格锚定分支处理"Sarah's annual salary"式同主语同属性换词复述；显式回指语+不同实体守卫处理"the Mehta stuff"式尾称），**重复回放守卫**（被忘值以任何措辞重入均被边界拦截，restore 需显式再授权+新值）。擦除边界行不存任何明文值——存储介质上被遗忘的数据不可恢复、也不可从边界行反推。原子性：绑定失败即 503 拒绝整个写入，绝不静默跳过（同步可检红线的另一面）。

### 1.6 与短期记忆的边界

会话尾 10 条消息（snapshot tail）仅作提取期指称消解上下文，不进检索池；检索池由事实层+原文段层构成，全量跨会话。块边界 overlap 由评测机分块语义去重（幂等+槽位合并）承接。

## 二、工程质量与可部署性

### 2.1 接口稳定性

| 接口 | 契约 | 稳定性设计 |
|---|---|---|
| POST /add | 4 字段 Receipt 恰形 | (request_id+载荷哈希) 幂等：重放返原 Receipt、异载 409；并发互斥经 revision 乐观锁+引擎串行队列 |
| POST /search | `{data:[{id,content,score,created_at}]}` | 无状态读路径；降档形态仍有结果 |
| GET /health | 引擎就绪 2xx | models:"ok"\|"degraded" 如实上报不阻断（部分网关无 /models，硬阻断会误杀可用部署） |

**降档哲学（语义/能力二分）**——写入口的失败语义分级：语义面拒绝（操作绑定失败、证据核验不符）**fail-closed 503，绝不假 200**；能力面故障（网络/超时/坏 JSON/核验不可达）**降档为确定性方案 200+degraded 标记**。死端点端到端实测：LLM 完全不可用时 health degraded、add 1.6s 降档成功、检索命中——基座两轮 0/100 全灭的根因形态已关闭。

### 2.2 部署与启动

单容器 Docker 非交互启动（compose 默认 offline 形态）；本地链路（colima/镜像源/apt 镜像）已走通并文档化。双配置矩阵：`release-offline.env`（确定性提取，评测主形态）/ `release-enhanced.env`（模型提取+核验恢复管线，v5 组合）。**LLM 披露**（README 表）：enhanced 形态的提取与核验模型、用途、降级行为一览；offline 形态零外部依赖。三库经 submodule 指针锁定为一次可复现实验（workspace pin service+eval 精确 commit）。

### 2.3 性能预算（实测）

| 路径 | 赛题预算 | 实测 |
|---|---|---|
| add | ≤120s | offline 确定性提取秒级；enhanced 有界恢复管线兜底；全量回放 4,622 请求零超时失败 |
| search | ≤60s | BM25+仲裁亚秒；评测客户端 55s 超时余量充足 |

### 2.5 质量保障体系（四层验证 + 契约固化）

1. **单测 508 项**（70 文件）：契约+回归+对抗反例——每条宽松匹配原语必须带反例测试（数字子串不连坐/单 bigram 新记录存活/描述符无值/marker 无明文），评审轮教训固化为工程纪律。
2. **契约校验 12/12**（eval 侧黑盒：幂等/隔离/top-k/遗忘路径…）。
3. **全量回放**：4,622 条官方请求重放到独立实例（fresh 数据目录），逐样本比对失败面。
4. **A/B 逐题配对**：两构建同源回放，按 qid 配对统计 wins/losses/503 转化——隔离作答噪声的评测方法论。

**四条固化契约**（测试守卫，改动需显式决策）：①退休指令不可绑定=原子拒绝；②语义拒绝不降级（坏 JSON≠语义拒绝）；③续传模式严格契约（release 关闭）；④聚合卡成员粒度擦除。

## 三、创新性与可扩展性

### 3.1 创新点（全部已实现并验证）

1. **令牌化擦除边界 + 全哈希回声索引**：遗忘的正确数据结构不是删除标记而是「值摘要+词数+短语 bigram 哈希索引」的边界行——换词复述（"Sarah's annual salary"）、显式回指（"the Mehta stuff"）、领格换词三类回声路径分别有专属抑制分支与反例守卫；被忘数据在存储介质上不可恢复、边界行不可反推。A/B 中 15 个原子拒绝样本转化为可判定、零新增拒绝、过擦除零例。
2. **成员粒度的派生物擦除**：聚合卡（跨会话列表物化）与遗忘共存——卡按成员粒度吸收擦除、永不连坐兄弟成员的原文、restore 成员后家族卡自动重建。物化视图类系统（含商业实现）普遍在此连坐。
3. **语义/能力二分降档**：把写入失败语义沿「语义拒绝 vs 能力故障」一刀切开——前者 fail-closed 保住同步可检红线，后者降档保住可用性。上游两轮 0/100 全灭的根因（能力故障被当作语义拒绝 5xx）由此关闭，且与续传严格契约按写入模式二分合成。
4. **判分对齐工程**：从判分函数（must_include 词面命中/stale_value 60% 检查率/harmful_extra）反推存储与排布——值串原样嵌入聚合卡、意图三分仲裁当前/历史/轨迹切面、意图规则 1,544 题零假阳性全量回归固化。
5. **A/B 逐题配对方法论**：评测噪声（同证据不同判）只能靠配对设计隔离——本轮 27 个表面回归中 13 个实证为两臂证据完全相同的作答噪声，避免了对噪声做错误归因的返工。

### 3.2 可扩展性

- **表示版本线 v2→v10**：数据表示沿 sourceFormat 版本演进，旧目录有格式守卫（不兼容即显式拒绝并提示），新能力（擦除边界/原文操作/转移核验/覆盖打包）逐版本叠加不破坏旧数据。
- **配置门实验矩阵**：MEMORY_EXPERIMENT_*（聚合卡/佐证/生命周期/时间/事件视图/覆盖打包）全部默认关、release 显式开——单因子消融即改一行配置；workspace configs/ 沉淀 40+ 实验配置。
- **模型层可替换**：offline（零依赖）/enhanced（openai 兼容端点+核验恢复管线）零代码切换；核验协议信封独立于具体模型。
- **评测基建可复用**：requests.jsonl 全量回放 + 状态级 sqlite diff + 逐题配对，构成任意后续改动的回归门。
